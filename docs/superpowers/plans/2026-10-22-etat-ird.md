# État des IRD — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Relever décodage (image, son, déchiffrement, programme), débit d'entrée, état matériel et journal de chaque IRD, en tirer six nouvelles alertes, et remplacer le graphe BER par une bande « État » par IRD.

**Architecture:** `ird.py` lit les nouveaux champs et, toutes les 10 s, l'état matériel et le journal (`IrdReader.read()` renvoie un `IrdReading`). Chaque mesure reçoit un code d'état (0 à 3) calculé à l'enregistrement, que la bande affiche et que l'historique agrège par maximum. Le détecteur gagne les règles par IRD, la hiérarchie des alertes et la comparaison par programme.

**Tech Stack:** Python 3.12 bibliothèque standard, SQLite, uPlot (déjà présent), `unittest`.

**Spec:** `docs/superpowers/specs/2026-10-22-etat-ird-design.md` (prolonge `2026-10-21-multi-porteuses-design.md`).

## Global Constraints

- Lecture seule ; requêtes IRD autorisées : `xml=<refresh/>`, `xml=<status type="status"/>`, `xml=<logs type="logs"/>`.
- `status` et `logs` toutes les 10 s par IRD, délai maximal 1 s chacune ; leur échec n'est jamais un échec de lecture.
- Persistance de 3 s pour `video_lost`, `audio_silent`, `not_descrambled`, `ts_stopped` ; délai interrompu = repart de zéro.
- Gravités : `video_lost`, `not_descrambled`, `ts_stopped`, `hw_fault` → critical ; `audio_silent` → warning ; `ird_log` : `information` → info (événement fermé aussitôt), `warning` → warning, autre → critical.
- Motifs de fermeture exacts : « réception perdue », « IRD injoignable », « IRD retiré ».
- Codes d'état de la bande : 3 rouge = lock perdu ; 2 violet = image perdue, programme non déchiffré ou flux d'entrée arrêté ; 1 orange = BER > 0 ou son absent ; 0 vert = normal ; absent = gris.
- Textes en français ; tests `python3 -m unittest discover tests -v`.

## Review Focus

1. **Programme sans son** (aucune voie audio configurée) : jamais de « Son absent » (tâche 3, `test_no_audio_configured_no_alert`).
2. **Message d'information permanent** du journal (« Program is scrambled », `nTimeEnd = -1`) : événement fermé aussitôt, jamais « en cours » indéfiniment (tâche 3, `test_info_log_closed_immediately`).
3. **IRD redémarré** (les `nId` reculent) : pas de rafale d'anciens messages, pas de doublons (tâche 3, `test_log_ids_going_back_rebaseline`).
4. **Lock perdu pendant une image perdue** : « Image perdue » fermée avec « réception perdue » et pas rouverte avant le retour de la réception (tâche 3, `test_lock_lost_closes_decode_alerts`).
5. **Requête `status` ou `logs` en échec** : la mesure de l'IRD est quand même enregistrée, aucune alerte « injoignable » (tâche 1, `test_reader_extras_failure_keeps_sample`).

### Task 3: Détection

**Files:**
- Modify: `monitoring/detect.py`
- Test: `tests/test_detect.py`

**Interfaces:**
- Consumes: `IrdSample`, `IrdHealth`, `IrdLogMessage`.
- Produces :
  - `on_ird(ts, serial, name, s)` gère en plus `video_lost`, `audio_silent`, `not_descrambled` et `ts_stopped`, avec les conditions, la persistance de 3 s et les gravités du §4 de la spec.
    - **Détails** : « IRD 1 : image perdue », « IRD 1 : son absent (0/5 voies) », « IRD 1 : programme non déchiffré », « IRD 1 : flux d'entrée arrêté ».
    - **Hiérarchie** : quand `locked` ou `ts_locked` est faux, ces quatre alertes ouvertes sont fermées avec « réception perdue » et ne peuvent pas se rouvrir avant le retour du lock.
  - `on_health(ts, serial, h: IrdHealth) -> list[dict]` gère `hw_fault`, avec le détail « IRD 1 : surchauffe, ventilateur, alimentation » (seulement les défauts présents).
  - `on_logs(ts, serial, messages: list[IrdLogMessage]) -> list[dict]` gère `ird_log`, avec le détail « IRD 1 : <texte> ».
    - **Premier appel** pour une série, ou `nId` maximal en recul : mémoriser les messages sans créer d'événement.
    - **Messages `information`** : événement fermé aussitôt.
    - **Autres niveaux** : événement ouvert jusqu'à ce que `ended` devienne vrai ou que le message disparaisse.
  - `on_state(..., "ird:<s>", "down", ...)` ferme en plus, avec « IRD injoignable », les quatre alertes de décodage et `hw_fault`.
  - `on_alone(ts, carriers, reachable, names, programs: dict[str, int | None] | None = None)` :
    - les alertes de réception comparent tous les IRD de la porteuse ;
    - `video_lost` et `not_descrambled` ne comparent que les IRD qui ont le même `programs[s]` (connu) ;
    - le détail reste celui d'aujourd'hui.
  - `remove_ird` ferme aussi ces alertes, avec « IRD retiré ».
